# Transport experiments (shared with Stream from Mac)

The main application now implements the network-only flow. See [current setup and acceptance tests](../../docs/NETWORK-STREAMING.md). `radio.ts` re-exports the production transport, so synthetic experiments use the same 192 kbps MP3 framing, headers, and bounded buffering. `npm run prototype:benchmark` remains a Linux/Mac transport-only test; it does not claim native capture or Sonos success.

`npm run prototype:bridge -- --synthetic` retains the standalone loopback test server. Its optional `--lan` server on port 3001 is **not required** by Current; the integrated app uses its existing HTTP port. Do not expose private bearer URLs. `prototype:capture:build` now invokes the same local native build as `capture:build`, and the standalone native launcher uses that helper. Use Current's integrated session for silence keep-alive, capture status, radio metadata, grouping, stop/reconnect, and supervised cleanup. The earlier `capture.swift` is an archived prototype source, not the built production helper. The current helper and positive browser allowlist live under `native/mac-audio`.

No native helper was compiled in the cloud. Grant macOS recording permission only for an explicit capture session; no protected media URLs or credentials are extracted. Stop terminal experiments with Ctrl-C. Do not play the live HTTP audio back into the captured browser, which can create feedback.
